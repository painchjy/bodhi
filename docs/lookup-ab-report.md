## 7. 口径说明（为什么这么算）

- **查询次数**：一次 `knowledge_lookup` 内部可能打 1–5 次库/图（AND 空 ⇒ 自动降级 OR；图不可用 ⇒ 退 PG）⇒ **MCP 调用次数 ≠ 实际查库次数** ✗ 现在按 **PG + Neo4j 的真实往返**统计（`ke_stats` 在 `psql()` / `neo4j.query()` 逐次回填行数）。
- **成功/失败**：**返回空记录的往返算失败**；`有结果的往返` = rows>0 的次数；`空查询占比` = 空 ÷（空 + 有结果）；`有结果调用占比` = 该次调用最终 `hits>0` 的占比。
- **总耗时**三层：`单次检索`（一次工具调用）／`每问检索总耗时`（同一问题多轮合计）／`端到端`（`agent_duration_ms`，含 LLM 思考与全部工具；只有 C2 真值能给）。
- **问题归组**：同 `qid`（业务编号）必同组；否则字符 bigram 相似度 ≥ 阈值（默认 0.62，`--group-threshold` 可调）归同组；`q_shape`（词数档 × 类/实例/文本）单独成列 —— “关键字数量/层次不同”算不同类问题 ✓。
- 结论**不在此自动化判定**：本表只保证样本可比、指标可复算 ✓
