## 3. 自拟「文字案例」3 个（覆盖 R1 的违规 / 合规 / 信息不足）

> 写法仿需求 block 59-63 的正文口径（"3.4 部署架构 / 3.4.1 灾备方案"）。

**案例 A（违规 —— 期望 `violate`）**
> 3.4 部署架构
> 本系统等级为 **B 级**。生产部署方案为：**同城单机房云上部署**（张江云），异地采用**数据级备份**（内蒙云），应用不双活、不具备自动接管能力。数据库为主备架构，主库单实例。
> **期望判定**：违反 R1。B 级必须 **同城+异地**（此条满足），但最低灾备要求为 **同城云上：跨云双活/跨云热备**（实际单云单机房 → 不满足）、**异地云上：多云多活/多云热备**（实际数据级备份 → 不满足）→ **2 条问题**，级别：严重。

**案例 B（合规 —— 期望 `pass`）**
> 3.4 部署架构
> 本系统等级为 **C 级**。生产为**同城+异地**部署：同城为**云上单云双活**（浦江云两机房），异地为**云上数据级备份**（贵州云）。同城两机房之间数据库跨机房同步，网关双活。
> **期望判定**：满足 R1（C 级最低：同城云上 单云双活 ✅；异地云上 数据级备份 ✅）→ 无问题。
> *（需求自带节选可视为同类合规样本：3 机房 3 租户 5 副本 OB + SLB 主备 + REDIS 跨机房主从）*

**案例 C（信息不足 —— 期望 `unknown` + `knowledgeGaps` + 人工协助）**
> 3.4 部署架构
> 本系统为**重要系统**，采用**同城双活**，异地有**灾备**，满足高可用要求。数据库采用分布式集群，具备故障自动切换能力。
> **期望判定（关键）**：**不得直接判 pass/violate**。缺失：① **系统等级**（未写 A/B/C/D → 无法确定适用哪档最低要求）② **部署载体**（云上/云下未写）③ **灾备具体模式**（"灾备"≠ 多云热备/数据级备份等受控词）④ **同城/异地的云与机房**。
> → 输出 `verdict=unknown` + `knowledgeGaps[等级, 载体, 灾备模式]` → **发起人工协助子任务**（需求 block 92），并在"文档质量问题"里登记。
