# 技术方案：订单服务下游故障隔离

## 背景
订单服务同步调用库存、支付和风控三个下游。下游超时后请求线程被长时间占用，曾导致其他接口也出现超时。

## 目标
下游故障时，订单服务仍能处理核心下单请求，不因一个下游不可用而耗尽线程和连接资源。

## 方案
为每个下游调用增加超时、熔断和 fallback。熔断器打开后快速失败，返回缓存结果或明确的降级响应；半开状态只放少量探测请求。不同下游使用独立线程池和连接池。

## 方案与目标的关系
下游连续失败时，快速失败避免调用线程继续等待；独立资源池阻止故障跨下游扩散；fallback 保证核心流程可继续。方案不修复下游根因，也不保证消息送达。

## 验收关注点
需要说明超时时间、熔断条件、fallback 内容、资源池隔离和恢复探测；不能把熔断写成消息可靠性保证。
