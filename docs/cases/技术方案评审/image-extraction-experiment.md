## 3. 三条硬发现（对 PoC 设计影响最大）

### F1：图1 的"同城"要靠**云名里的地点语义**（**可推测**，但要标置信度）

- 图1 只有云名（浦江云、张江云、内蒙云）与 AZ 名，**没有城市标签**；但**云名称本身就含地点信息**（浦江/张江 = 上海；内蒙 = 内蒙）→ **可从名称推测**，不需要一张"必须人工维护、否则判不出来"的外挂映射表（**用户 2026-10-01 裁定：云名称已包含地点信息，可以推测**）。
- 图2 相反，大区标签「上海／内蒙／贵州」直接印在图上 → 同城/异地**可纯靠图像判定**。
- **同一条规则、两张图，信息充分度不同**。这说明：
  1. 判定必须允许"**地名词义推测**"作为输入，但**推测值要打折置信度**（例：仅凭名称推测 0.75；若知识库登记过该云/机房 → 0.95）→ 低于阈值仍进人工协助（需求 block 92）。
  2. 该映射属于**轻量 L1 受控实例**（~10 条；登记后判定可复现），**保鲜成本低**（新增云/机房才改 1 行）→ 走策略 §2.2 的"是否需要本体 × 成本 × 收益"决策卡。
- **对 A/B 的意义**：轨道 A（纯 NL）也可能"猜对"，但**不可复现、给不出证据**；轨道 B 给出"推测值 + 置信度 + 依据"。**所以 A/B 的关键差异不在"结论对错"，而在 `证据可回溯率` 与 `外部知识依赖数`** —— P5 指标里单列。

### F2：图上存在**语义歧义** → 必须产出"待澄清"，而不是选一个

- 图片2 中分片 **80-99 同时出现在内蒙云与贵州云**（且两云之间有一条"数据同步"）。合理猜测是"内蒙为主、贵州为同步副本"或反之，但**图上没有写明**。
- 结论：**识别管道必须输出 `ambiguity[]`（含两处坐标 + 两个候选解释 + 置信度）**，由 S5 的规则审核把该条判为 **unknown/需澄清**。若让模型"二选一"，则 A/B 的结论不可信。
- 这是"**置信度阈值 + 人工协助子任务**"机制（需求 block 92）**第一次有了真实用例**，可写进 P4 用例集。

### F3：识别产物必须**三层分离**（否则证据链不可复核）

| 层 | 内容 | 落到哪 |
|---|---|---|
| **结构层** | 云/AZ/机房/单元/分片区间/网关/应用/中间件/DB + 连接与方向 | L1 实例（可图查询/可比较） |
| **语义层** | 图例含义（红=应用故障）、故障域范围、跨云同步、"同城/异地"等结论 | L1 标注（带 `confidence` + `derivedFrom` 证据） |
| **载体层** | 原图本身 | L3 指针（文档 id + 图序号 + **坐标/区域**），任何结论都可回看原图 |

> 只做第一层 → 判不出灾备；只做第二层 → 无据可查；缺第三层 → 人工无法复核。三层都留，才满足"证据可复核"。

## 4. 实验 B：WeKnora 侧能力核验（实测，非推测）

### 4.1 实测事实

| 项 | 实测结果 |
|---|---|
| 视觉模型是否注册 | ✅ `models` 表有 `WeKnoraCloud 视觉`，`type=VLLM`，`status=active`，id=`479800af-4a72-4561-a0d2-9095e8e48cf1`，`base_url=https://weknora.weixin.qq.com`，`parameters` 含 `supports_vision` |
| 云端可达性 | ✅ 实测 HTTP 200（DNS 0.03s / 总 0.40s） |
| 凭证 | ❌ 该模型 `api_key` **为空**（对照：DeepSeek 的 KnowledgeQA 模型 `api_key` 已有值） |
| app 侧多模态开关 | ✅ `config.yaml` → `knowledge_base.image_processing.enable_multimodal: true` |
| KB 级视觉配置 | ❌ 8 个知识库 `vlm_config` **全部** `{"enabled": false, "model_id": ""}`；`image_processing_config.model_id` 也为空 |
| 文档解析 | docreader 容器健康；环境含 `DOCREADER_ODL_*`（布局/混合解析）、`DOCREADER_PDF_EXTRACT_EMBEDDED_IMAGES`、`DOCREADER_IMAGE_OUTPUT_DIR` → **具备"抽文档内嵌图"能力**；另有 `WEKNORA_CHAT_ATTACHMENT_OCR_MAX_PAGES=8` 等附件 OCR 并发参数 |
| 交付包影响 | `tools/delivery/export_db.py` 会把 `vlm_model_id` 脱敏剥离（客户需自行配置）——**意味视觉模型不进交付包，属环境级配置** |

### 4.2 结论：可以用，但要先"启用"

- **能力存在**：WeKnora 有 `VLLM` 类型的视觉模型 + 多模态开关 + 抽图管道 → **P3 的图识别可以用 WeKnora 原生路径**（KB 上传图片 → `vlm_config` 调用视觉模型 → 生成描述 chunk → S4 规范化落库）。
- **启用动作（2 步，需你确认后执行）**：
  1. 给目标 KB 打开视觉：`vlm_config = {"enabled": true, "model_id": "479800af-4a72-4561-a0d2-9095e8e48cf1", ...}`（模型若走 WeKnoraCloud，需先在 WeKnora 侧完成该模型的登录/凭证配置）；
  2. 因 `WeKnoraCloud` 是**外部云服务**（数据出域），若 POC 要求不出网，则改为**自有 VLM endpoint**（同字段换 `base_url`+`api_key`）——字段结构不变，切换成本低。
- **兜底路径（不依赖 WeKnora 凭证）**：外部多模态 LLM 直读 + 用我们已有的落库通路（MCP `save_knowledge` / 表格导入）写 L1 实例与证据。**两条路径必须共用 §5 的同一份输出契约**，否则 P5 的 A/B 不可比。

### 4.3 难度评估（回答 D4"识别难度应该不高"）

| 维度 | 评估 |
|---|---|
| 视觉难度 | **低**：清晰截图、无旋转/无手写、小字仅在分片数字与单元编号（0.85）；水印轻微干扰 |
| 语义难度 | **中**：需领域语义（云名↔城市、图例含义、主备/新旧模式词表） |
| 工程难度 | **中**：需"坐标 + 置信度 + 待澄清"三段式落库与人工复核闭环（工具已在：`save_knowledge`/人工确认字段） |

## 5. 提取契约 v0（S4 的输入输出约定，双路共用）

```json
{
  "source": {"doc_id": "…", "file": "图片1.jpg", "figure_no": 1, "page": 12, "size": [1712, 1347]},
  "extractor": {"kind": "weknora_vlm|external_vlm|human", "model": "…", "run_id": "…", "at": "…"},
  "nodes": [
    {"id": "cloud.pujiang", "type": "Cloud", "label": "浦江云", "bbox": [0.28, 0.20, 0.47, 0.95], "confidence": 0.98},
    {"id": "dc.zhangjiang.az3", "type": "AZ", "label": "张江云AZ3", "bbox": [0.72, 0.86, 0.95, 0.99], "confidence": 0.95}
  ],
  "edges": [
    {"from": "cloud.pujiang.oss", "to": "cloud.zhangjiang.oss", "type": "sync", "evidence": "虚线+『同步』", "bbox": [0.42, 0.72, 0.72, 0.78], "confidence": 0.6}
  ],
  "annotations": [
    {"key": "dr.pattern.homocity", "value": "跨云双活", "derivedFrom": ["cloud.pujiang", "cloud.zhangjiang", "kv.cloudcity.浦江云", "kv.cloudcity.张江云"], "confidence": 0.85}
  ],
  "ambiguity": [
    {"topic": "shard.80-99", "candidates": [{"value": "内蒙主机房", "confidence": 0.5}, {"value": "贵州同步副本", "confidence": 0.5}],
     "bbox": [[0.44, 0.88, 0.52, 0.98], [0.72, 0.88, 0.80, 0.98]], "needHuman": true, "reason": "同区间双现，图上未写主备"}
  ],
  "knowledgeGaps": [
    {"need": "云名→城市", "missing": ["浦江云", "张江云"], "impact": "无法判定『同城』", "confidenceWithout": 0.0}
  ],
  "todo": [{"action": "确认跨云同步方向", "assignee": "human", "blocks": ["dr.pattern.homocity"]}]
}
```

**门禁（写进 S4 技能）**
1. 每个 `node/edge/annotation` **必须有 `bbox` 或 `evidence`**，否则不予落库（= 可复核性硬门禁）；
2. `confidence < 阈值`（建议 0.8）**必须**进 `ambiguity[]`/`todo[]`，且**不允许**把不确定项写成结论；
3. 结论类 `annotation` 必须写 `derivedFrom`（可追溯到节点或知识项）；
4. **缺知识**要显式输出 `knowledgeGaps`（F1 的机制），由 S1/S6 补进知识清单，而不是让模型自己"脑补"。
