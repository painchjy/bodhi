# 技术方案：配置中心读取性能优化

## 背景
配置中心的高频读取接口 QPS 持续上升，数据库读压力成为瓶颈。配置数据读多写少，允许秒级旧值。

## 目标
降低读取延迟和后端数据库读压力，同时明确缓存一致性边界。

## 方案
采用 Cache-Aside：读请求先查本地缓存，未命中再查数据库并回填；配置更新提交数据库后删除缓存，并设置 TTL 兜底。缓存只放可容忍短时旧值的配置项。

## 方案与目标的关系
缓存命中路径绕过数据库，降低读取延迟和数据库压力；写后失效和 TTL 控制陈旧窗口。方案不提供跨系统强一致，也不适合频繁变化且不能陈旧的数据。

## 验收关注点
需要说明缓存键、失效顺序、TTL、容量和降级；不能把缓存写成强一致性保证。
