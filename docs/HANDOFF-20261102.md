## 2. 铁律（违反就会被工具/巡检挡住）

1. **本体编译程序不许随意改**：`tools/ontology-compiler/**` 是产物生成器；改本体只改 `ontology/sources/*.ttl` → `python3 tools/ontology-compiler/compile.py compile`。除非任务明确要求，不要“顺手优化”编译器。
2. **更新本体文件 = 模拟前端上传**：`POST /bodhi/ontology/upload`（`filename` / `content` / `module_id`；默认 `write_source=true, compile_after=true, project_wiki=true`），或 `POST /bodhi/ontology/load`（`model_id` + `compile`）。
   **不要**手工改 `artifacts/**`，也不要直接写本体库页（`save_knowledge` 会拒：`ontology_kb_readonly`）。
3. **工具/技能只认类型与属性**，不写领域名词（`tests/biz_terms.txt` 扫描命中 = 0）；本体（`ontology/*.ttl`）不出现实例名。
4. **后端改动必须用 MCP/HTTP 实测**，不写临时 Python 脚本代替系统功能、不改数据绕过门禁；**前端改动必须开浏览器看控制台**。
5. **改函数前先全库搜引用**，一次改完所有调用点（`_section_form_text`、`_lookup_impl` 都是这么定位的）。
6. 写库一律 `dry_run` 先给 diff 再 apply；两段式（retag / rollback / 权限）必须 preview → ticket → apply。
