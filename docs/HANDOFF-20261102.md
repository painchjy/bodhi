3. **工具/技能只认类型与属性**，不写领域名词（`tests/biz_terms.txt` 扫描命中 = 0）；本体（`ontology/*.ttl`）不出现实例名。

**口径**：

| 列 | 来源 | 含义 |
|---|---|---|
| 参数 chars | `agent_steps.tool_calls.args` | 模型发出的工具参数大小 |
| 回执 chars | 优先日志 `Completed ... output=N chars`；缺失才退回 `agent_steps.result` | 工具结果实际字符数 |
| 本轮 prompt | 日志 `[Round-N][ctx] drift actual_prompt` | 该轮 LLM 实际输入 token（含工具 schema/历史） |

| tool_results | 日志 `breakdown tool_results` | 工具结果在上下文中的 token 估算 |
| cumulative usage | `messages.usage` | 整条 assistant 累计值，只做校验，**不当每轮值** |

> 读表口径：第 N 轮的 `本轮 prompt` 已经包含第 N-1 轮工具回执；所以第 N 轮的
> `较上轮增量` 就是“上一轮工具调用之后 prompt 增加了多少”。最后一轮工具回执进入
> `FinalAnswer` 的 prompt，不在 ReAct Round 表里。

### 9.1 VLM 请求体抓取（2026-11-11）

`image_read` 原先把发给 VLM 的 HTTP body 只放在内存里，回执只有 `request_bytes`；
排障时无法拿原始 body 重试。现在加了一个默认关闭的开关：

```text
BODHI_VLM_DUMP_REQUEST=1
```

重启 MCP 后，每次真实调用会写：

```text
state/doc_parse/vlm/<doc_id>_img<N>_<hash>.request.attempt1.json
state/doc_parse/vlm/<doc_id>_img<N>_<hash>.request.attempt2.json   # thinking 重试时
```

文件是**实际发送的原始 JSON bytes**（含图片 data URL，不含 `Authorization`），权限 `0600`。
可直接重试：

```bash
curl -sS -X POST "$BODHI_VLM_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $BODHI_VLM_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @state/doc_parse/vlm/<...>.request.attempt1.json
```

同时 `vlm` 诊断块新增：

```text
http_status / response_content_type / response_bytes
response_keys / choices_count / choice0_keys
response_head（仅 content 为空时，前 500 字符）
```

用于区分 HTTP 200 的 `choices=[]`、网关错误体、非 OpenAI 格式。
`detail=compact/full` 只改变回执裁剪，不改变请求 body，两个模式抓到的 body 大小应一致。
