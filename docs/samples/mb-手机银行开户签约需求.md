# 手机银行「注册 / 实名验证 / 签约」需求说明（样例）

## 一、业务背景与范围

个人客户希望在手机上使用银行服务，不再依赖柜面。业务上要求「先注册、再实名、后签约」，
并且客户身份信息**以法定证件为准**，渠道侧不得自行认定客户身份。本需求覆盖：

- **手机银行注册**：客户自助录入信息、验证手机号码、建立登录凭据；
- **实名验证**：采集并核实客户身份三要素；未通过不得开通转账类服务；
- **手机银行签约**：签约本人账户与渠道服务（协议、限额、设备绑定）；
- 不在本次范围内：账户开立、信贷产品申请、柜面服务。

## 二、需求正文（约 550 字）

### R1 客户开通手机银行与实名验证

客户在手机银行 App 自助开通服务，须先**注册**：录入手机号码与姓名，用短信验证码核实号码，未解绑前一个号码只能绑定一个用户。注册后进入**实名认证**：客户须提供**姓名、证件种类（居民身份证、护照等）、证件号码**，系统调用实名认证（联网核查）服务核实三要素是否一致、证件是否有效；三要素完全一致方可通过，任一项不符或核查不可用时拒绝开通并提示到柜面办理，同时记录失败原因与核查流水号。三要素相同即同一客户，是客户信息的唯一确定依据：客户信息以三要素为锚归集至 ECIF 并分配客户编号；核实通过前只能保留待认证的注册用户，不得建立正式客户编号。此外可采集补充信息（性别、出生日期、地址、电子邮箱、职业等），并记录注册、登录、认证等行为日志。

### R2 手机银行签约

实名认证通过后，客户对拟开通的账户与服务进行**签约**：选择本人名下账户（本行借记卡/信用卡；他行卡须先验证账户），签署《手机银行服务协议》并配置渠道权限与限额（转账限额、理财与基金风险测评、消息通知、设备绑定）。签约以客户三要素为准关联账户与协议：同一渠道下同一账户只允许一条有效签约，重复提交视为幂等成功，返回已存在的签约结果。签约结果写入手机银行用户管理服务，并同步 ECIF 的「客户-账户」关系与渠道开通标志；签约变更（限额调整、换绑设备、解约）必须留存变更记录与时间戳，供审计追溯。

## 三、采集与核实要素

**3.1 注册环节采集**

| 要素 | 采集方式 | 核实方式 | 备注 |
|---|---|---|---|
| 手机号码 | 客户录入 | 短信验证码 | 登录凭据；未解绑时一个号码一个用户 |
| 姓名 | 客户录入 | 仅格式校验（**不核实**） | 实名后以证件姓名为准 |
| 登录密码 / 生物特征 | 客户设置 | 本地校验 | 渠道凭据，不进客户主数据 |
| 设备指纹 | 自动采集 | — | 用于设备绑定与风控 |

**3.2 实名验证环节（三要素，采集 + 核实）**

| 要素 | 是否三要素 | 采集 | 核实 | 归属 |
|---|---|---|---|---|
| 姓名 | ✅ | 客户录入 | 与证件库比对 | ECIF |
| 证件种类 | ✅ | 客户选择 | 枚举合法、与号码匹配 | ECIF |
| 证件号码 | ✅ | 客户录入 | 与证件库比对 | ECIF |
| 证件有效期 / 发证机关 | — | 客户录入（可选） | 是否在有效期内 | ECIF |
| 核查结论 / 核查流水号 / 核查时间 | — | 核查服务返回 | — | 渠道留存 + 审计 |

**3.3 其他客户基本信息（可采集）**：性别、出生日期、联系地址、电子邮箱、职业、工作单位、客户风险等级（内部评定）。

**3.4 客户行为记录（渠道过程数据，非客户信息）**：注册、登录、密码重置、实名认证（成功/失败）、签约/解约、限额调整、设备换绑、交易；每条含行为标识、客户或用户、行为类型、结果、时间、设备、来源 IP，**只追加、可审计**。

## 四、业务规则

| 编号 | 规则 | 级别 |
|---|---|---|
| `BR1` | 三要素一致且证件在有效期内，方可通过实名验证 | 严格执行 |
| `BR2` | 未通过实名验证不得建立正式客户编号、不得开通转账类服务 | 严格执行 |
| `BR3` | 一个手机号码在未解绑前只能绑定一个手机银行用户 | 严格执行 |
| `BR4` | 同一渠道下同一账户只允许一条有效签约；重复提交按幂等成功处理 | 严格执行 |
| `BR5` | 客户信息以三要素为准归集，渠道侧信息不得覆盖证件信息 | 严格执行 |
| `BR6` | 签约变更必须留痕（变更内容、时间、操作者） | 严格执行 |

## 五、待确认问题

1. 三要素是否唯一且不可变？客户改姓名（更正错字、婚姻变更）后是否仍指向同一客户？
2. 手机号码是「客户联系方式」还是「渠道账号」？换号时是否改变客户身份？
3. 一名客户是否允许有多个手机银行用户（如两个手机号）？
4. 他行卡签约是否需要四要素/五要素（增加银行卡号、银行预留手机号）？
5. 行为记录的保留期限，以及是否允许关联到三要素（隐私合规）。
