# 小微企业经营圈手机签约服务需求说明（样例）

> ⚠️ 本文件是**为流程验证而编写的样例需求**（非真实业务材料），是 `docs/samples/mb-手机银行开户签约需求.md`
> 的**增量需求**：个人客户在已实名的基础上，新增一个小微企业经营签约身份及其资金安排。
> 用途：① 增量需求的知识提取验证；② 涉企账户关系与资金穿透类规则验证。
> 本文件只写业务需求，**不含设计与实现内容**。

## 一、政策与战略背景

**国家战略层面**

1. **中央金融工作会议（2023 年 10 月）** 提出做好「科技金融、绿色金融、**普惠金融**、养老金融、数字金融」五篇大文章，
   其中普惠金融的重点对象是**小微企业**与民营经济。
2. **国务院《关于推进普惠金融高质量发展的实施意见》**：提高小微主体融资可得性、降低综合融资成本、
   健全「**敢贷、愿贷、能贷、会贷**」长效机制，减少对抵押担保的过度依赖。
3. **金融监管总局普惠信贷年度工作要求**（近年提法概括为「保量、稳价、优结构」）：
   普惠型小微企业贷款增速不低于各项贷款增速、有贷款余额户数不低于年初（即「两增」口径），
   并对**首贷户**扩面、**无还本续贷**、期限与现金流匹配提出要求。
4. **中国人民银行** 通过支农支小再贷款、普惠小微贷款支持工具等结构性货币政策工具引导资金投向，
   配合 LPR 改革推动降低小微企业实际融资成本。
5. **供应链金融与「银税互动」**：以真实交易背景（合同、发票、订单）与纳税数据增信，
   把「主体信用」扩展为「**交易信用**」，是小微无抵押融资的主要路径。
6. **反洗钱与穿透式监管**：《反洗钱法》（2024 年修订）与受益所有人信息管理要求，
   叠加贷后「**经营流与资金流匹配**」要求 → 涉企资金必须可核对、可穿透、可追责（防挪用、防套取、防洗钱）。

## 二、需求正文

### R1 小微企业经营用户签约（个人客户新增企业签约身份）

已完成实名认证的个人客户，可以在手机银行**新增一个小微企业经营签约用户**（同一个 App、同一登录身份下切换）。
企业侧身份验证**仍以三要素为准**：办理人姓名、证件种类、证件号码须与其已实名的个人身份一致，
并补充企业主体信息（企业名称、统一社会信用代码、营业执照、法定代表人、经营地址、行业与规模）。
一个个人客户可签约**多个**小微企业；一个小微企业可授权**多个**经办人，每笔经办动作须记录授权人与授权范围。

### R2 经营信息提交与征信评级

签约时须提交**近三个月经营流水**（本行账户流水、他行流水导入或支付渠道流水，需可核对交易对手与摘要），
并授权查询企业与法定代表人的**征信信息**、可选的税务与发票数据。系统依据流水规模、交易对手稳定性、
征信记录、纳税与行业情况自动给出**信用评级**，据此形成建议额度、利率与期限；经贷后/审批人员复核后，
确定该企业的**可贷额度**与单笔用款金额上限。评级或额度变化须通知客户并留痕。

### R3 建立经营圈与上下游账户关系

为该小微企业建立**经营圈**：以企业及其核心交易对手为中心，纳入上下游账户（供应商、经销商/客户），
每个账户关系要记录角色（上游供应商 / 下游客户 / 核心企业）、关系确认依据（交易事实、合同、发票）、
生效与失效时间。经营圈一经确认，圈内账户之间的**资金划拨可在核准额度内授权交易**，
无需逐笔提交审批；圈外支付须单独申请。

### R4 用款与授权交易（无抵押、额度内）

本产品**无抵押**，以信用方式或由政府性融资担保、风险补偿基金增信。额度内授权交易支持随借随还，
区分受托支付与自主支付，并设置单笔限额与日累计限额；所有用款须与经营用途匹配（采购、备货、运费等），
不得用于投资、理财、房地产等禁止用途。

### R5 还款与宽限期

支持按日计息、随借随还、无还本续贷。产品设置**还款宽限期**：宽限期内归还本息的，**免收利息**
（宽限期天数与免息口径由产品参数定义，并在签约协议中明示）。超出宽限期按合同约定计息，
并触发风险处置流程（提醒、限制新增用款、人工核查）。

### R6 账户隔离、取现限额与分行后台审核

经营圈资金使用账户与客户的**个人账户相互隔离**：独立账号、独立用途、资金不得混用；
经营圈资金原则上在圈内账户间划拨。**取现到个人账户每月设有限额**，未超限额可直接办理；
**超过限额须由签约分行后台审核**（人工审批、说明用途、留存审批痕迹）后方可执行。
所有资金变动须完整留痕（发起人、授权人、审核人、时间、金额、用途），可追溯、可核对。

## 三、要素清单

**3.1 个人客户侧（复用已实名信息）**：姓名、证件种类、证件号码（三要素）、手机号码、登录凭据、设备指纹。

**3.2 企业侧**：企业名称、统一社会信用代码、营业执照、法定代表人及其三要素、行业与规模、经营地址、成立年限、
开户账户、企业授权经办人及其授权范围。

**3.3 经营与信用信息**：近三个月经营流水（含交易对手、金额、日期、摘要）、纳税与发票数据（授权可选）、
企业征信报告、法定代表人个人征信报告、评级结论与评级时间、可贷额度与单笔上限。

**3.4 经营圈与账户关系**：经营圈标识、成员账户、成员角色（上游供应商 / 下游客户 / 核心企业）、
关系确认依据（交易事实 / 合同 / 发票）、生效时间、失效时间、关系变更记录。

**3.5 资金与授权**：额度、已用额度、单笔限额、日累计限额、划拨指令（发起人、收款账户、金额、用途）、
授权记录（授权人、授权范围、有效期）、圈外支付审批记录。

**3.6 还款与宽限**：放款金额、计息起止、还款计划、宽限期天数、免息金额、逾期信息、风险处置动作。

**3.7 取现与审核**：取现限额（每月）、当月已取现金额、超限额申请、审核机构（签约分行）、审核人、审核时间与结论。

## 四、业务规则

| 编号 | 规则 | 级别 |
|---|---|---|
| `BR1` | 企业签约身份必须绑定一个**已完成三要素实名**的个人客户，且经办人三要素与该个人身份一致 | 严格执行 |
| `BR2` | 近三个月经营流水为额度评估的必要材料；征信查询必须取得客户与法定代表人授权 | 严格执行 |
| `BR3` | 可贷额度由评级结果与增信方式确定；单笔用款金额不得超过剩余可贷额度 | 严格执行 |
| `BR4` | 资金划拨仅限经营圈内账户；圈外支付或超额支付须单独申请审批 | 严格执行 |
| `BR5` | 本产品无抵押，采用信用方式或政府性融资担保、风险补偿基金增信 | 严格执行 |
| `BR6` | 宽限期内归还本息的免收利息；超宽限期按合同计息并触发风险处置 | 严格执行 |
| `BR7` | 经营圈资金使用账户与个人账户隔离，资金不得混用 | 严格执行 |
| `BR8` | 取现到个人账户每月限额；超限额须经签约分行后台审核通过后方可执行 | 严格执行 |
| `BR9` | 授权交易须留存授权人、授权范围、有效期与审核痕迹；授权不得转让 | 严格执行 |
| `BR10` | 涉企资金变动纳入反洗钱监测：同一实际控制人或受益所有人关联的账户之间资金往来须可核对、可穿透 | 严格执行 |

## 五、待确认问题

1. 企业侧身份是否沿用自然人「三要素」？还是企业另有「名称 + 统一社会信用代码 + 法定代表人」的企业三要素？
   （两者都需要时，以哪一方作为唯一性口径？）
2. 经营圈上下游账户可以是**他行账户**吗？若可以，流水与授权如何取得、如何保证交易真实性？
3. 宽限期免息的资金来源与会计口径（产品定价让利 / 财政贴息 / 内部转移定价）？
4. 可贷额度与个人客户既有消费/经营额度是否共享、是否互斥？
5. 超限额取现的审批层级（签约分行 / 总行）与时限承诺（T+? 完成审核）？
6. 穿透口径：实际控制人与受益所有人的识别阈值、更新频率、与年度报告的一致性校验责任方。
7. 经营圈的圈外支付是否需要白名单，还是逐笔审批？

## 六、与前置需求（个人手机银行）的关系

| 类别 | 内容 |
|---|---|
| **复用** | 个人客户的三要素实名；登录凭据与设备绑定；协议签署与电子签名能力；账户与限额的管理界面 |
| **新增** | 企业主体与企业签约身份；企业授权经办关系；近三个月经营流水与征信评级；可贷额度与单笔上限；经营圈及上下游账户关系；额度内授权交易；还款宽限期与免息；经营圈账户与个人账户隔离；取现限额与签约分行后台审核 |
| **需核对的一致性** | ① 同一自然人身兼法定代表人 / 经办人 / 借款人时，三要素与授权口径是否一致；② 个人手机号码在经营圈场景中的用途（通知渠道还是账户标识）；③ 个人客户的既有权限（转账限额、设备）与企业签约身份的权限是否叠加或互相约束 |

## 七、本需求的两个验证用途

1. **增量需求抽取**：与 `docs/samples/mb-手机银行开户签约需求.md` 对照使用，
   验证增量文档中「复用的既有实体」与「新增的实体与关系」是否被正确区分、不会重复建页。
2. **涉企关系与资金穿透**：经营圈成员、经办授权、实际控制人与受益所有人之间的账户关联，
   用于验证「资金往来是否指向同一控制人 / 受益所有人」这类穿透与反洗钱规则的判定。
