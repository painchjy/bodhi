# 技术方案知识提取（技能）

> **只提取与承载原文，不做判定**；判定归「文档评审」技能。
> **v0.2.1（2026-10-08）**：补「可信度＋转人工阈值」字段并与图像识别契约对齐；补「参考规范不可得（待澄清）／规则未维护（不适用）」标准用语；补阶段接续点声明。
> **阶段口径**：见领域知识《技术方案评审流程》的「阶段流转（S1–S7）」；本技能**只声明自身接续点**，不复制整表。

## 0 第 0 步：先定四件事
1. **锁定规则**：取本次业务策略下的规则清单，挑出「判定所需知识」非空的重点规则（严格执行优先）；规则定义／参考规范缺失或未挂业务策略 → 结论用语固定为「规则未维护（不适用）」并入问题台账；
2. **锁定目标库**：工作知识库＝由领域指定的任务工作知识库（技术方案评审场景＝「技术方案评审任务知识库」）；只写这一个库，技能与工具调用不得越出此库范围；会话绑多库必须显式指定；
3. **锁定来源**：本轮方案附件（按标题/文档名定位）；
4. **锁定阈值**：可信度阈值默认 **0.6**（评审组长可按轮次调整），低可信度处置默认「转人工协助」。
5. **声明接续点**：当前位于 **S2 内·重点规则推理之前**；产物＝知识项清单（含可信度与转人工标记）；正常交回「文档评审」进入推理；不可得／低可信度转 **S4 人工协助**。

## 1 主流程
1. **need**：把规则的「判定所需知识」拆成待提取清单（例：部署架构规则→系统等级、部署方式、灾备方式、现状与目标、设备申请情况；开源软件规则→技术栈及版本）；清单报用户确认后再提取；
2. **extract**：按来源类型分流，只依据本批正文，不脑补——
   - 正文/表格：分批正文＋关键词定位取原句，记录章节与原文位置；
   - 图像（部署图、技术栈勾选表截图）：调 `image_recognition`，按契约取「逐项取值＋来源类型（图）＋**可信度**＋**是否需人工确认**＋**建议动作**」；挡板期返回 `_mock=true`、`_source=stub:image_recognition`；
3. **confidence**：逐项给**可信度（0–1）**＋来源类型（文/表/图）＋**是否低于阈值**＋**是否需人工确认**＋**建议动作**（进入推理／转人工协助）；图像与跨文档推断降级；
4. **assist**：以下三种情形**都必须**发起人工协助子任务（挡板期带 `_mock`），**不得**用猜测值顶替：① 可信度低于阈值；② 提取不到；③ 参考规范不可得（结论用语：参考规范不可得（待澄清））；
5. **store**：知识项落工作知识库（写入必传会话编号，身份字段不手填），同任务同批次，供后续轮次复用。

## 输出契约
每条知识 ＝ {`规则标识`、`知识项`、`取值`、`原文位置`、`来源类型`（文/表/图）、`可信度`、`是否低于阈值`、`是否需人工确认`、`建议动作`}。
- 不可得的也要出一条，取值写「不可得（原因）」；参考规范相关写「参考规范不可得（待澄清）」；
- 挡板来源的条目必须带 `_mock` / `_source`，引用它的结论必须标**「模拟数据」**；
- 写库类先 `dry_run` 预览，人工确认后写入。

## 门禁
- 规则缺失或「判定所需知识」为空 → 停下问用户，不自行发挥；
- 可信度低于阈值 → **不进入推理**，转人工协助或标「受限：知识不可得」；
- 挡板数据必须带 `_mock` 标；
- 提取结果与原文冲突以原文为准，两条都留。

## 纪律
1. 不改本体；缺类/缺属性 → 只写改进建议（`adviceCategory=本体类`）；
2. 只写工作知识库；类型一律 `ontology_types` 现查，不凭记忆；
3. 一轮一批，不指望整篇一次性提取；超时/截断就把批调小（8k→4k→2k）；
4. 落库必传会话编号（运行时注入），身份字段不要手填；
5. 收尾 `audit_scan`：本次写入的知识页都要有原文依据（无来源即红）。
