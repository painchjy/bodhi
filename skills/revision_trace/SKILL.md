# 评审轮次比对与问题溯源（技能）

> **v0.2.0（2026-10-08）**：固定输出契约并新增「专家反馈」性质标注；补阶段接续点声明；补落库会话编号纪律。
> **阶段口径**：见领域知识《技术方案评审流程》的「阶段流转（S1–S7）」；本技能**只声明自身接续点**，不复制整表。

## 0 第 0 步
1. 取任务：`review_task_api`（挡板）取流程编号/名称/本轮与上一轮附件版本；
2. 取上一轮问题台账（编号、级别、触发规则、文档位置、修改建议）、上一轮已识别知识与待确认清单；
3. 目标库＝由领域指定的任务工作知识库（技术方案评审场景＝「技术方案评审任务知识库」）；只写这一个库，技能与工具调用不得越出此库范围；
4. **声明接续点**：当前＝**S6 后续轮次评审**；产物＝「修改-问题」对照表＋未溯源清单；责任人＝智能体；出口条件＝无「沉默修改」；下一步＝**S7 问题总结**（或回 **S5** 反馈项目组）。

## 1 主流程
1. **load_prev**：载入上一轮问题台账、待确认清单与附件；
2. **diff**：按章节比对两轮附件，列出修改章节与修改前后文字（逐字）；
3. **trace**：把每处修改溯源到上一轮问题（同位置／同触发规则／同违规内容）；
4. **unresolved**：无法溯源的修改单独列出并标「需重新评审」，交回「文档评审」逐条评审；
5. **report**：输出对照表并落工作知识库；回写问题管理属写库类操作，**默认 `dry_run`**。

## 输出契约
每条 ＝ {`问题标识`、`修改章节清单`、`修改前后文字`、`溯源结论`（已溯源/未溯源）、`是否需重新评审`、`专家反馈`（**性质＝事实核查／评审结论**，并逐条对应到待确认项编号）}。
- 未溯源清单必须单列，不得并入已溯源项；
- 报告文字章节与对照表**去重且一一对应**。

## 门禁
- 溯源无把握不猜，宁可标「未溯源」；
- 回写默认 `dry_run`，人工确认后才写入；
- 挡板数据带 `_mock` 标与「模拟数据」提示。

## 纪律
1. 不改本体，不修改其它技能；
2. 只写工作知识库；类型一律 `ontology_types` 现查；
3. 落库必传会话编号；身份字段不要手填；
4. 收尾 `audit_scan`：本次写入的页都要有原文依据。
